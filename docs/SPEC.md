# Lens v3 — spec (supersedes ARCHITECTURE.md, V2_ONBOARDING.md, V3_VERCEL_YOUCOM.md)

The UI is the user's design: `docs/design/Lens Demo.html` (+ `docs/design/DESIGN-HANDOFF.md`). Match its look, markup, CSS, copy, interactions and keyboard/reduced-motion behavior exactly, EXCEPT the changes listed here. The design simulated everything; v3 wires it to real backends. Plain browser JavaScript (no React, no build step, no npm deps), hosted on Vercel (repo root static + `/api/*` Node 18+ functions, ESM, global fetch). No database, no accounts.

## Changes vs the design
1. **Analytics is removed** (nav button, page, data, filters popover, CSS that only it uses). Nav = Stack, Chat, Calendar (+ Settings on the right).
2. **No "demo" wording anywhere** — every integration is live. Remove "in demo", "Previewing a website scan for the demo", "Connected in demo", "Scheduled in demo", "Sample metrics", etc. Never label anything "real" either.
3. **Scan is real**: while the glass-lens animation plays (keep min duration 2650 ms / 950 ms reduced motion), call `lens.scanSite(url)`. The first onboarding agent message uses what was learned ("I read <name>: <one-line summary>. What does your company do?" style — but if the scan worked, ask the founder to confirm/correct the product description instead of asking cold). Scan failure → continue with the plain first question, no error wall (a small notice is fine).
4. **Onboarding chat is real AI** (OpenRouter, via `/api/ai`) via `lens.onboardTurn(...)`. Same 5 slots as the design (product, audience, goal, cadence 1–14 posts/week, voice), same order, one question per turn, follows up on vague answers (like the design's clarifications), parses cadence ("three times a week" → 3; out of range → ask again). When all 5 are filled, the agent's final message + the connection rows (Sculptex, LinkedIn) + "Save brand & open posts →" appear exactly as in the design. "Skip to posts →" keeps answers so far and fills the rest from the scan, then generic defaults. A typing indicator (three dots in an agent bubble) shows while waiting. If the AI is unavailable, the agent bubble says so plainly ("Lens AI isn’t available right now. …") and the Skip button still works.
5. **Stack items come from the backend**:
   - After onboarding (and on "Generate more"), call `lens.generatePosts({ brand, count: 3 })` → LinkedIn post drafts grounded in fresh You.com search results about the founder's field (trends, news, events). Each may carry `sourceUrl` + `sourceLabel`, rendered like the design's "Creator Economy Hack · Event source ↗" link (`<label> · Source ↗`).
   - Also call `lens.findDMs({ brand, count: 2 })` → DM drafts to people who publicly described the problem the product solves. Interleave DMs with posts in the stack (e.g. post, post, DM, post, DM).
   - Show a loading card state ("Drafting posts…" with the lens mark) while generating; "You're all caught up" + "Generate more" when empty.
6. **DM cards** (kind `'dm'`): same card shell, but the header shows a small "DM" chip + recipient/context instead of the LinkedIn mark; body shows the message; the source link (the person's public post) is shown; a **Copy** button inside the card copies the message (navigator.clipboard, with a textarea fallback) and notifies "Message copied." Below the card, the two decision buttons become **"I sent this"** (approve slot, check icon + text label) and **"I don't like this"** (decline slot, x icon + text label). Swipe right = I sent this (journal status 'Sent'); swipe left / "I don't like this" = ask `lens.revise({ kind:'dm', ... request: 'The founder did not like this message. Write a clearly different version.' })` and replace the card's copy in place (card stays on top), with the card's revision composer still available for specific feedback. DMs never go on the Calendar and are never sent by Lens. Review hint text for DM cards: "Copy the message, send it on LinkedIn, then mark it sent. Swipe left for a new version."
7. **Revisions are real AI**: the card's revise composer, the scheduled post page's "Revise with Lens", and Chat proposal edits all call `lens.revise` / `lens.brainstorm`. Keep the design's validation/feedback behavior (error line under the composer on failure).
8. **Chat is real AI** (OpenRouter, via `/api/ai`) via `lens.brainstorm({ brand, messages, proposal })` → `{ reply, proposal? }`; "Add draft to stack" queues the proposal exactly like the design.
9. **Visuals**: posts may have `visual: { src, link?, provider }`. The card shows the image in the design's `.post-visual` slot (object-fit cover, same radius/height, alt text) instead of the placeholder orb. In the pencil editor add a "Visual" row: **Render with Sculptex** (if Sculptex connected), **Remove visual**; it calls `lens.createVisual({ provider: 'Sculptex', prompt })` with a prompt derived from the post. Visuals come from Sculptex only. If Sculptex is not connected, show a one-line hint linking to Settings.
10. **Calendar**: unchanged design behavior (week view, arrows, Today, drag to another day with suggested ET slot, open → edit + revise), plus:
    - A small rounded **pill banner** at the top of the Calendar: "Leave Lens open so scheduled posts can send." with an X button (aria-label "Dismiss") that hides it; remember dismissal in localStorage.
    - **Auto-publish**: every 30 s (and on load / tab focus), for each Scheduled post whose slot ≤ now: if LinkedIn is connected → `lens.publish(post)`; on success journal status 'Posted' (+ `postedUrl`), notify "Posted to LinkedIn."; on failure keep it Scheduled, mark `error`, notify once. If LinkedIn isn't connected, mark it due (no spam) — the scheduled post page shows "Due — connect LinkedIn to post" or a **Post now** button when connected.
    - Posted posts show on the calendar with a subtle posted style (check icon) and open read-only with a "View on LinkedIn ↗" link when `postedUrl` exists.
11. **Settings**: Connections rows are live (Connect starts the provider's sign-in redirect; Disconnect clears it; show account name when known; show a short error under the row on failure). Brand memory download/upload and Download logo as designed. "Erase local data" also calls `lens.disconnectAll()`.
12. **Connections everywhere** (onboarding + Settings) use `lens.connect(provider)` / `lens.disconnect(provider)` and render from `lens.connections()`; after an OAuth redirect returns, the app resumes the same view (onboarding stays at the connections step).

## Front-end files
- `index.html` — the design's markup/CSS adapted (CSS may move to `css/app.css`); loads `./js/app.js` as `type="module"`; favicon + header wordmark from the design (assets in `assets/`).
- `js/app.js` — the design's script adapted to the above; still `innerHTML` rendering with `esc()` for every interpolated value (security: never inject unescaped AI output or URLs; validate `sourceUrl`/`postedUrl`/visual `src` to http(s)/data:image only).
- localStorage key `lens-v3` for brand/posts/journal/brainstorm/proposal; MCP + LinkedIn connection state is NOT in localStorage.

## Service contract — `js/services/lens.js` (all async unless noted; throw `Error` with a readable `.message`; `.code` may be 'no-relay' | 'no-key' | 'credits' | 'rate' | 'not-connected' | 'redirect')
```js
init()                                   // call once on load: completes any OAuth return (Sculptex MCP, LinkedIn), refreshes status; returns { returnedFrom?: 'Sculptex'|'LinkedIn', error? }
connections()  // sync → { Sculptex:{connected, account?, error?}, LinkedIn:{connected, name?, picture?, canReply?, error?} }  // canReply: comment permission granted (absent = unknown)
onConnectionsChange(fn)                  // subscribe; returns unsubscribe
connect(provider)                        // may navigate away (OAuth); resolves when connected otherwise
disconnect(provider) ; disconnectAll()
scanSite(url)                            // → { name, summary, product, audience?, keywords: [] }
onboardTurn({ site, scan, answers, messages })  // messages: [{role:'agent'|'user', text}] → { reply, answers:{product?,audience?,goal?,cadence?(int),voice?}, done:boolean }
generatePosts({ brand, count })          // → [{ kind:'post', title, copy, sourceUrl?, sourceLabel?, visualIdea? }]
findDMs({ brand, count })                // → [{ kind:'dm', title, copy, recipient?, sourceUrl, sourceLabel }]
revise({ brand, item, request })         // item: {kind,title,copy} → { title?, copy, message }
brainstorm({ brand, messages, proposal })// → { reply, proposal?: { title, copy } }
createVisual({ provider, prompt })       // 'Sculptex' → { src, link?, provider }
publish(post)                            // → { id, url? }  (LinkedIn; includes image when post.visual.src is fetchable)
```
Backend modules behind it (owned by the backend agent):
- `js/services/you.js` — You.com relay client for `/api/you`: search, extract and status only (status caching with retry). 402 → code 'credits' with message "You.com is out of API credits for this key."
- `js/services/ai.js` — AI client for `/api/ai` (OpenRouter). Exports `chat({ system, messages, maxTokens, temperature, signal })` → text, `json({ system, prompt, shape, maxTokens, temperature, signal })` → parsed JSON (robust extraction + one retry with the parse error), `extractJson(text, expect)`, `status()` → `{ relay, key, model, confirmed }` (cached, retried on network errors). Codes: 'no-relay' (file:// or 404/405/501), 'no-key' (no OPENROUTER_API_KEY), 'credits' (402, message "OpenRouter is out of credits."), 'rate' (429), 'network', 'timeout'. Every LLM call in `lens.js` (scan summary, onboarding, posts, DMs, revisions, chat) goes through it. User-facing AI failures are provider-neutral ("Lens AI …"); only search/extract failures mention You.com.
- `js/services/mcp.js` — keep the existing multi-server MCP client (Streamable HTTP + OAuth 2.1 PKCE + dynamic registration, scopes/resource from PRM, sessionStorage only) but remove its dependency on the old React `store.js` (own tiny sessionStorage state + listeners).
- `js/services/linkedin.js` — browser side: `status()` via `GET /api/linkedin/me`, `connect()` → `location.assign('/api/linkedin/start?return=' + encodeURIComponent(location.pathname + location.hash))`, `disconnect()` → `POST /api/linkedin/logout`, `publish()` → `POST /api/linkedin/post`.
- `api/you.js` — You.com relay: `GET ?op=status`, `POST ?op=search|extract` (env `YOU_API_KEY`). No LLM ops.
- `api/ai.js` — OpenRouter relay (`POST https://openrouter.ai/api/v1/chat/completions`, `Authorization: Bearer $OPENROUTER_API_KEY`, `HTTP-Referer` = site origin, `X-Title: Lens`). Model = env `OPENROUTER_MODEL` || `google/gemma-4-31b-it:free` (callers cannot choose). `POST /api/ai` JSON `{ system?, messages: [{ role: 'user'|'assistant', content }], maxTokens? (64–8000, default 1500), temperature? (0–1.5) }`, body ≤ 200 KB, upstream timeout 55 s, `maxDuration` 60 in vercel.json → `{ ok: true, data: { text, model, finishReason } }` or `{ ok: false, status, error, code }` with code 'no-key' (500, "AI isn't configured on this deployment (OPENROUTER_API_KEY)."), 'credits' (402, "OpenRouter is out of credits."), 'rate' (429), 'invalid' (bad request body), 'forbidden' (403: a browser POST whose Origin / Sec-Fetch-Site shows another site), 'upstream' (anything else, including errors OpenRouter reports inside an HTTP 200; a non-JSON upstream body such as an HTML error page is never quoted in the message). `GET /api/ai?op=status` → `{ ok: true, key: boolean, model }`. No CORS headers, `Cache-Control: no-store`, never logs keys or bodies. The OpenRouter logic lives in `api/_lib/openrouter.js`. Scripts can still call the endpoint, so `OPENROUTER_API_KEY` should be a key with a credit limit set in OpenRouter. Temporary: `POST /api/you?op=agent` (old clients' AI calls, body `{ system?, messages | input, maxTokens?, temperature? }`) goes through the same OpenRouter logic and answers `{ ok: true, data: { text, model, finishReason } }`; remove it once tabs with the pre-OpenRouter client have aged out.
- `api/linkedin/start.js`, `callback.js`, `me.js`, `post.js`, `logout.js` — OAuth 2.0 authorization code flow with env `LINKEDIN_CLIENT_ID`, `LINKEDIN_CLIENT_SECRET`; redirect URI `https://<host>/api/linkedin/callback` derived from the request host (x-forwarded-host/proto) — registered value is `https://lensbeta.vercel.app/api/linkedin/callback`; scopes `openid profile email w_member_social` (+ `w_member_social_feed` when `LINKEDIN_FEED_SCOPE=1`); CSRF `state` in a short-lived HttpOnly cookie; access token stored ONLY in an HttpOnly, Secure, SameSite=Lax **session cookie** (no Max-Age → gone when the browser session ends) together with the member id (`sub` from /v2/userinfo) and name/picture; never returned to JS. `post.js` creates a post via `POST https://api.linkedin.com/rest/posts` (headers `LinkedIn-Version` current YYYYMM, `X-Restli-Protocol-Version: 2.0.0`; author `urn:li:person:<sub>`; commentary = title + blank line + copy, escaped per LinkedIn "little text" rules for reserved characters; visibility PUBLIC; distribution MAIN_FEED; lifecycleState PUBLISHED); if an image URL/data URL is provided, upload it via the Images API (`/rest/images?action=initializeUpload`, PUT bytes, then reference the image urn). Returns `{ id, url: 'https://www.linkedin.com/feed/update/<urn>/' }`. Verify current LinkedIn docs (learn.microsoft.com/linkedin) for exact endpoints/headers/escaping. Readable JSON errors; 401 from LinkedIn → clear cookie, `{ error:'LinkedIn session expired — reconnect.' }`.
- Old React app files are deleted: `js/lib.js`, `js/store.js`, `js/router.js`, `js/ui.js`, `js/demo-data.js`, `js/views/**`, old `css/**`, `404.html`, `.nojekyll`, old docs (ARCHITECTURE.md, V2_ONBOARDING.md, V3_VERCEL_YOUCOM.md). `dev/serve.py` stays (static + /api/you + /api/ai, Python 3.9 stdlib, same env vars and response shapes; note LinkedIn needs the Vercel deployment).

## v3.1 — listening, comment replies, Sculptex-first visuals (user request 2026-11-22)

**Listening (You.com).** After onboarding and whenever the stack refills (re-run if the last listen is older than 12 h, or on Generate more), `lens.listen({ brand })` runs several You.com searches (freshness month; community domains reddit.com, news.ycombinator.com, x.com, linkedin.com, indiehackers.com, producthunt.com plus the open web) for: the product/brand name, its competitors, and the problem it solves (from product/audience/keywords). The AI distills **pain points** (label, one-line detail, rough count, 1–3 short verbatim quotes with source URLs) and keeps the best **threads** (url, title, snippet, platform, community, author if visible, publishedAt, and for LinkedIn posts the activity URN parsed from the URL: `/posts/…-activity-<id>-…` or `/feed/update/urn:li:activity:<id>`). Saved in localStorage (`state.listen = { at, painPoints, threads }`) and summarized in Settings → Brand memory as "What people are saying" (top pain points, each with a source link). Posts, replies and DMs are all written from these pain points.

**Stack mix per refill** (cadence stays posts per WEEK, 1–14): `2 × cadence` post options, **3 comment replies**, **2 DMs**, interleaved (e.g. post, post, reply, post, DM, post, reply …). Skip kinds that have no material (e.g. no threads → no replies/DMs) without erroring.

**Comment reply cards** (kind `'reply'`): header chip "Reply" + platform (LinkedIn / Reddit / Hacker News / X / …) + community; shows the original comment/post being replied to as a short quote, then the draft reply (≤ 80 words, helpful first, references their words, discloses founder affiliation, no hard sell).
- **LinkedIn** (has `linkedinUrn`): approve (✓ / swipe right) = **post the reply through the API** via `lens.postReply(item)` → `POST /api/linkedin/comment` → `POST https://api.linkedin.com/rest/socialActions/{urlencoded urn}/comments` with `{ actor: urn:li:person:<sub>, object: <urn>, message: { text } }` (verify current docs/headers/escaping; the Comments API lists scope `w_member_social_feed` from the Community Management API product — requested only when env `LINKEDIN_FEED_SCOPE=1`; a 403 or other permanent failure turns the card into a copy-and-paste reply). Success → journal 'Replied' + notice "Reply posted on LinkedIn." with a link; failure → card stays, readable error. Requires LinkedIn connected (it's required at onboarding; if the session ended, show "Reconnect LinkedIn in Settings").
- **Other platforms**: like DM cards — **Copy** button in the card, an **Open thread ↗** link to the thread, below the card **I sent this** (journal 'Replied') / **I don't like this** (AI writes a clearly different version in place).
- LinkedIn reply decline = "I don't like this" → new version too.

**Sculptex-first visuals.** When Sculptex is connected, Lens should strongly prefer adding a Sculptex 3D render to posts whenever there's a plausible fit — and almost always when the company relates to 3D, architecture, CAD, hardware, products, manufacturing, games or design. `generatePosts` returns, per post, an optional `visual3d: { prompt, effort }`; the app then renders those automatically in the background (one at a time, card shows the rendering state, failures leave the post without a visual and a quiet notice). **Effort policy**: only `low`, `medium` or `high` are ever sent (never xhigh/max/ultra or similar); default `low`; the AI must pick the lowest effort that will still look good (renders only need to look good, not be manufacturable). In `renderWithSculptex`, find the tool's effort-like input (e.g. `effort`, `quality`, `detail`, `reasoning_effort`) from its inputSchema and pass the clamped value (map to the closest allowed enum value at or below `high`); if the tool has no such input, send nothing extra.

**Contract additions** (`js/services/lens.js`):
```js
listen({ brand, force })        // → { at, painPoints:[{label, detail, count, quotes:[{text,url,source}]}], threads:[{id,url,title,snippet,platform,community,author?,publishedAt?,linkedinUrn?}] }
generatePosts({ brand, count, painPoints })   // posts may include visual3d:{prompt, effort:'low'|'medium'|'high'}
findReplies({ brand, threads, count })        // → [{ kind:'reply', platform, title, quote, copy, sourceUrl, sourceLabel, linkedinUrn? }]
findDMs({ brand, threads, count })            // now uses listened threads
postReply(item)                               // LinkedIn only → { url? }; codes 'not-connected' | 'not-linkedin'
createVisual({ provider:'Sculptex', prompt, effort })  // effort clamped to low|medium|high, default 'low'
```
